# Syriana Energy — خطة البناء (نسخة 1.0 — 22 أكتوبر 2026)

منصة SaaS لمراقبة منظومات الطاقة الشمسية والتحكم بها: إنفرتر وبطارية ليثيوم، ثم أجهزة الإنترنت لاحقاً.
عربي وإنجليزي، تنبيهات، ذكاء اصطناعي، API و MCP. لأي صاحب بيت، ولشركات التركيب.

## القرارات المقفولة
- **المنتج:** SaaS كامل من البداية، وأول عميل هو بيت محمد (Home Samer Alkahlan)
- **الاسم:** Syriana Energy
- **البنية:** خدمة مستقلة. أودو للزبائن والاشتراكات والفواتير فقط، ويُربط عبر API
- **السيرفر:** سيرفرنا. سيرفرات ShineMonitor الصينية مصدر قراءة مؤقت فقط
- **التسعير:** اشتراك شهري أو سنوي، ودفعة واحدة فقط لقطع العتاد (مثل جسر البطارية)
- **البناء:** وكلاء Sonnet 5.5 يبنون، ووكيل مستقل يراجع ويختبر قبل أي دمج أو نشر

## البنية التقنية
| الطبقة | التقنية |
|---|---|
| الواجهة | Next.js 16 + Tailwind، تطبيق PWA يتثبّت على الموبايل، RTL/LTR، ترجمة بـ next-intl |
| الخلفية / API | Python 3.12 + FastAPI (REST + WebSocket للبيانات الحية) |
| الجامعون | عمّال Python غير متزامنين: drivers لكل ماركة، ويعملون بنظام الطوابير |
| قاعدة البيانات | PostgreSQL 16 + TimescaleDB للقراءات، مع ضغط وسياسة احتفاظ حسب الباقة |
| الطوابير والكاش | Redis (مع arq أو Celery) |
| التنبيهات | محرك قواعد، وقنوات: تلغرام بوت، إيميل (Mailgun/SMTP)، Web Push. ثم واتساب و SMS للمدفوع |
| الذكاء الاصطناعي | Claude عبر Cloudflare AI Gateway: مساعد بالعربي، ملخص يومي، كشف الحالات الشاذة |
| MCP | خادم MCP (streamable HTTP) بأدوات: قراءة الحالة، التاريخ، التنبيهات، وأوامر التحكم مع تأكيد |
| الفوترة | أودو (العملاء، الاشتراكات، الفواتير) عبر webhook/API، والدفع: Stripe / Paymob / شام كاش |
| التشغيل | Docker Compose ثم Coolify، و Cloudflare (DNS + HTTPS + WAF)، والأخطاء على Sentry |

## نموذج البيانات (المختصر)
- `tenants`: الحساب، وقد يكون بيتاً أو شركة تركيب
- `users`: المستخدمون، مع الأدوار (owner / installer / viewer) و 2FA
- `sites`: موقع أو بيت تابع لحساب
- `devices`: الأجهزة (inverter / battery / network)، مع driver، الرقم التسلسلي، و PN
- `credentials`: بيانات ربط مشفّرة (AES-GCM)، مثل token لحساب ShineMonitor
- `readings`: hypertable في TimescaleDB، فيها `(device_id, ts, metric, value)` أو أعمدة جاهزة لكل نوع
- `events`: الأحداث، مثل انقطاع الدولة، الأعطال، وتغيّر وضع التشغيل
- `alert_rules`، `alert_channels`، `notifications`: قواعد التنبيه وقنواته وسجل الإشعارات
- `commands`: سجل أوامر التحكم (من أرسل، القيمة القديمة والجديدة، النتيجة)
- `plans`، `subscriptions`: الباقات والاشتراكات، مع مزامنة من أودو
- `api_keys`: مفاتيح API و MCP لكل حساب

## نظام الـ Drivers (قابل للتوسّع)
كل driver يطبّق نفس الواجهة: `discover()` و `read_realtime()` و `read_settings()` و `write_setting()` و `read_history()`.
1. `eybond_cloud`: ShineMonitor API عبر حساب الزبون. **الأول**، ولا يحتاج أي عتاد
2. `eybond_direct`: نوجّه الـ datalogger إلى سيرفرنا، ونستقبل رسائل Modbus أو بروتوكول Voltronic بغلاف Eybond. **يحتاج تجربة على بيت محمد**
3. `voltronic_serial`: عبر جسر محلي (ESP32 أو Raspberry Pi) بكابل RS232 أو USB
4. `peicheng_bms_ble`: بطارية BMS-TOOL عبر جسر ESP32 بجانب البطارية (BLE FFF0/FFF1/FFF2)
5. لاحقاً: `smartess`، `solarman`، `deye_modbus`، `jk_bms`، `jbd_bms`، `ubiquiti_airos`، `mikrotik`

## المراحل
### المرحلة 1 — النواة وبيت محمد (الأسبوع 1)
- هيكل المستودع، Docker، قاعدة البيانات، المصادقة
- driver `eybond_cloud`، وقراءة إنفرتر SN 96322507123757 كل 30 ثانية
- لوحة عربية: تدفق الطاقة، البطارية، الحمل، الشمس، الدولة، ورسوم بيانية لليوم
- بوت تلغرام: تنبيهات البطارية المنخفضة، رجوع وانقطاع الدولة، الحمل الزائد، والأعطال

### المرحلة 2 — SaaS (الأسابيع 2–4)
- تسجيل الزبائن، تعدد الحسابات، أدوار شركات التركيب
- الباقات والحدود، والربط مع أودو للفوترة
- لوحة الإدارة: الزبائن، الأجهزة المتصلة، الاشتراكات، والأعطال
- التحكم: أولوية الخرج والشحن، تيار الشحن، الصافرة. **مع حدود آمنة وتأكيد وسجل لكل أمر**
- الواجهة الإنجليزية، والمساعد الذكي، والملخص اليومي، وخادم MCP، ووثائق API

### المرحلة 3 — الاتصال المباشر والبطارية (الأسبوعان 5–6)
- تجربة `eybond_direct` وتوجيه الـ datalogger إلى سيرفرنا
- جسر ESP32 للبطارية، وبرنامجه الثابت (firmware)، وطريقة ربطه بالحساب

### المرحلة 4 — الشبكة (لاحقاً)
- صحن LiteBeam (airOS API) والراوتر MikroTik: السرعة، الإشارة، وسجل الانقطاعات وسببها

## الأمان
- HTTPS في كل مكان، و 2FA، وكلمات السر مشفّرة بـ argon2، وبيانات ربط الأجهزة مشفّرة
- سجل تدقيق لكل أمر تحكم، وحدود قيم آمنة لكل إعداد حسب جهد البطارية (24 أو 48 فولت)
- عزل بيانات كل حساب على مستوى قاعدة البيانات (Row Level Security)

## طريقة العمل مع الوكلاء
- كل مهمة لها فرع (branch) وطلب دمج (PR)
- وكيل Sonnet 5.5 يبني، ووكيل مراجعة مستقل يقرأ الكود ويشغّل الاختبارات ويجرّب الواجهة
- الدمج إلى `main` فقط بعد نجاح الاختبارات و CI. سيرفر التطوير ينشر من `develop`، والإنتاج من `main`
